## SOLVED — reusable for every later electrical task (in dockerfiles/maxwell_solver/mse_axisymmetric.py)

- **2*pi*r weighting is available in DEVSIM**, but only on a genuine 2-D mesh built with
  `create_2d_mesh` + `add_2d_mesh_line(dir=)` + `add_2d_region`, with `raxis_variable` and
  `raxis_zero` set, via the COMMANDS `cylindrical_node_volume` / `cylindrical_edge_couple`.
  `set_parameter(CoordinateSystem="cylindrical")` is accepted and does nothing.
  Verified against an analytic disc volume.
- **A contact only registers if its box covers a region of a DIFFERENT material.**
  Same-material boxes give zero contacts and NO error. This silently cost most of a session.
- **The Newton matrix is singular without analytic Jacobian edge models**
  (`EField:Potential@n0/@n1`, `DField:Potential@n0/@n1`). It assembles fine and only the solve
  reports it.
- DEVSIM ships its own reference silicon physics at
  `devsim/python_packages/simple_physics.py` (`SetSiliconParameters(d,r,T)`,
  `CreateSiliconPotentialOnly`, `CreateSiliconPotentialOnlyContact`). This is the validated
  path and the module should be rewritten on top of it rather than hand-rolling Poisson.
  `examples/diode/diode_common.py` shows the pattern.

## FOUND THIS WAKE — a measurement trap that invalidated probes

A 1-D mesh in DEVSIM has **no `y` coordinate**: `get_node_model_values(name="y")` returns 0.0 for
every node. Any doping set with `init_from="y"` on a 1-D mesh dopes on a constant, silently.
My 1-D reference junction ran "successfully" this way and reported V_bi = 0.0000.
The 2-D grid is unaffected (`y` spans the domain correctly), so the 2-D probe results stand.

## NOT SOLVED — the junction does not match theory

Measured V_bi 966.6 V (and 808.7 V in a full cm-unit variant) against 0.8124 V analytic, while
the solve converges to AbsError 1e-11. Consistently ~1000x too large across BOTH SI and CGS
unit systems, which means it is not a unit-conversion factor: the missing physics is the

## Wake 3, ROOT CAUSE FOUND (11-09)

The domain-dependence has a clean explanation, measured directly:

  z = +-9.87e-07 m  ->  phi = +-0.4167 V   (= V_bi/2 at each contact)
  metal contacts    ->  0.0000 V (pinned, correct)

Across a 1 um domain the total drop is 0.833 V, distributed LINEARLY.
Across a 94 nm domain it is the same total, also linear.

So the boundary condition is right and V_bi is right. What is missing is
SCREENING. A potential-only Poisson solve with FIXED doping cannot form a
depletion region: there are no mobile carriers to move, so the field is
uniform and V_bi ramps over the whole domain, whatever its length.
"V_bi = 0.83337 V, 0.0000% error" on the narrow domain was a COINCIDENCE
of choosing the domain ~= one depletion width. It is not agreement.

CONCLUSION: 2.3 needs the drift-diffusion equations (electron and hole
continuity + Poisson, coupled), which is what the row actually asks for
("drift-diffusion with the 2*pi*r weight"). The potential-only buildup
was scaffolding and cannot pass the width criterion by construction.

What is reusable and now proven:
  - 2*pi*r weighting: real 2-D mesh + raxis_variable/raxis_zero + the
    cylindrical_node_volume/cylindrical_edge_couple COMMANDS.
  - contacts need a different-material region under the box.
  - every edge model needs its analytic Jacobian (:Potential@n0/@n1).
  - 1-D DEVSIM meshes have no y coordinate (silently 0.0).
  - DEVSim ships simple_physics.py with the equilibrium contact model.

Next step is a coupled DD solve on the same (r,z) machinery. Not started.


## Wake 4: coupled DD attempted, NOT converged (11-09)

Root cause from wake 3 confirmed: potential-only Poisson cannot screen.

Built _build_mesh / _build_device / _build_dd_device / solve_abrupt_junction_dd
using DEVSIM's own simple_physics (CreateSiliconPotentialOnly ->
CreateSolution(Electrons, Holes) -> CreateSiliconDriftDiffusion ->
CreateSiliconDriftDiffusionAtContact). The model set assembles and iterates;
it does NOT converge.

Hard-won API facts, all measured:
  - CreateSiliconDriftDiffusion calls CreatePE, which needs Electrons and
    Holes to be SOLUTIONS first: "Electrons must exist". CreateSolution.
  - carrier solutions are log-form and must start strictly positive:
    "Solution Variable has negative or zero value before update".
    Seed to majority equilibrium; set_node_values WITHOUT init_from (with
    init_from="y" the seed is overwritten by the z coordinate and goes
    negative, giving exactly that error with a value ~ -1e-6).
  - SetSiliconParameters OVERWRITES Permittivity with eps_si*eps_0 where
    eps_0 = 8.854e-14 F/cm. Re-state it after calling.
  - still Convergence failure! with AbsError ~1e17 (= the doping number)
    whether the mesh is in metres or centimetres and whether Permittivity
    is F/m or F/cm. So the remaining unit/scaling error is NOT simply the
    geometry unit; the continuity equations mix NetDoping (cm^-3) with
    EdgeCouple in a way I have not yet matched.
